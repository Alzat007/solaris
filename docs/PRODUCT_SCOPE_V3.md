# SOLARIS · 掌中星系：经典区域探索与图文科普

版本：v3 · 2026-10-04
用途：放入当前项目，作为产品范围与内容规则的最新说明。
状态：开发要求，不是功能完成报告；本文件没有访问或修改用户本机代码。

## 1. 用户已经明确的产品定义

SOLARIS 是以太阳系为入口的星球经典区域探索 App。
用户选择星球，再选择具有教育意义的代表性区域，通过接近转场进入该地点的图文探索，了解科学知识、探测历程或正面向上的历史事件。

这里的“探索”不是全星球自由漫游，不是完整城市三维重建，也不是必须完成任务或答题才能阅读。

完整产品范围必须保留：
- 现有太阳系中的每颗行星都有可进入的经典区域或观察主题。
- 地球内容更详细：覆盖各国首都，以及经过明确选录的世界著名城市。
- 每个地点有与地点准确对应的知识、故事和图片；历史事件只选择真实、正面向上的主题。
- 保留电脑端摄像头手势、键鼠和现有网页；继续适配 Fire TV 遥控体验。

此前“只做北京中轴线”“城市故事馆”“只有火星”的描述不能作为最终产品定义。
可以分批实施和录入内容，但必须区分最终范围、本轮交付、已完成和未完成。比赛展示的内容子集也不能冒称完整产品。
不擅自更换赛道，不为本轮新增手机、账号、AI 聊天或双屏配对支线。

## 2. 两条内容路径

非地球：太阳系 → 星球 → 经典区域列表/球面标记 → 接近转场 → 地点科普与探测故事 → 返回。

地球：太阳系 → 地球 → 国家/城市目录或搜索 → 城市 → 地标/事件 → 图文故事 → 返回。
国家列表是筛选方式，不强迫用户逐层点击；支持直接搜索城市并转到其位置。
“世界名城”与“首都”是两类标签，可重叠，不把所有名城误标为首都。

地球完整目录需要声明采用的数据源、范围和版本。支持一个国家关联多个带角色/生效日期的首都记录，不把“一国只有一个永远不变的首都”写死进程序。对存在不同表述的地理条目记录来源及说明，不自动编造或替用户作立场判断。不先写一个未经核实的国家总数。

名城目录采用可解释的人工选录与来源，不让模型随意生成“全球最著名城市排名”。支持以后追加。

## 3. 经典区域：真实位置、现象或探测里程碑

每颗星球的经典区域数量由内容与资料决定，不强制每颗都有相同数量或类型。

首批可核验示例：
- 火星 · 奥林帕斯山：地貌、规模、轨道影像、观测与认识过程。[S1, S2]
- 火星 · 维京1号着陆点：1976年着陆、地面影像、科学工作。[S3]
- 火星 · 杰泽罗陨石坑/毅力号着陆区域：探测里程碑与古水环境研究。[S4]
- 木星 · 大红斑：风暴观测与探测资料，不是固体地面的登陆点。[S5]
- 土星 · 行星环：环的组成与探测故事，不是可供步行的实体平台。[S6]

其他行星也要建立经典区域目录，但具体名称、位置、图片、故事必须按来源核验。没有真实地面图时可用轨道影像、雷达图、地形可视化或明确标注的示意，不伪造地面摄影。

太阳不是行星；新增月球或其他卫星时保留正确类别及所属天体，不把它们算入八大行星。

### 科学准确性边界

截至本次核对，载人火星登陆仍是未来目标，不得把任何火星探测器着陆点写成“宇航员第一次登陆点”。[S7]
“首次”必须写清条件。1971年火星3号着陆与1976年维京1号的持续成功地面探测不是同一概念，优先以明确的任务名称与日期命名，而不是模糊宣传。[S3]

山、峡谷等自然区域不一定发生过人类现场活动。可以讲“该区域是什么”和“人类如何认识它”，不能为补齐事件数量编造登山、考察、发现或登陆。
科学尚未定论的内容须保留条件和不确定性，例如不能把寻找生命线索写成已经发现生命。
高度、尺寸等数据须包含单位、测量口径和来源，不能混用相对基准面高度与基底到山顶高度。
气象结构、轨道图和历史观测要标注时间，不能把旧照片等同当前实时景观。

## 4. 地点页面的完整形态

每个地点采用共用模板，至少呈现：
1. 名称、所属星球/城市、位置说明和一句话介绍。
2. 主图或适合该素材的轻量场景，并展示素材类型。
3. 核心知识：这个地方是什么、为什么值得了解。
4. 精选故事：具体时间、事件、地点关系、简短经过与教育意义。
5. 图集与可选时间线；图注逐张对应。
6. 可展开的详细资料、事实来源、图片署名和返回入口。

首层正文保持短而可读，详细内容可主动展开；中英文分别核对。
不使用每个地点完全相同的套话，不强制答题，不要求用户一直举着手才能阅读。
首个正式内容包可每地点先完成一个真实故事，再增加数量；不得把这个批次规模误写为最终范围。

事件和地点是可多对多关联的：一个事件涉及多个地点时，只在相应地点讲与其准确相关的部分。
关系须区分“事件在此发生”“对该区域的远程观测/研究”“仅主题相关”。
任务控制在地球进行，不代表整个事件现场在火星；城市级事件不自动绑定任意地标的精确坐标。

## 5. 正面向上的选题规则

建议主题：科学发现、太空探索、教育普及、文化艺术、文化遗产保护、体育交流、公共建设、公益互助、生态保护与合作。

“正面”是选题原则，不是改写事实的许可：
- 只收录能核验的事件，不制造某地的“第一”“最大”“改变世界”等称号。
- 不把战争、暴力、歧视等包装为值得颂扬的事件，不进行党派宣传或政治人物评价。
- 不为保持积极语气把科学争议写成定论、把失败写成成功。
- 可以选择某地的一段建设或保护故事，但不得假装这是该地全部历史。
- 没有可靠的合适事件时，标记待编审，或先发布自然科普内容；不能编造“正能量”填满目录。

## 6. 图片与素材

必须分别核对“事实可靠”和“素材允许使用”。NASA等机构网页也可能包含第三方版权素材。[S8]

每张图记录：原始页面、作者/机构、许可与许可页面、要求的署名、拍摄或制作时间、地点、素材角色、裁剪/增强色/拼接情况、是否AI示意。

角色至少区分：历史事件现场、当前或近年地标配图、轨道影像、科学可视化、艺术示意。
当代照片不标成历史现场；AI图不能冒充历史摄影或真实探测影像。
宽幅图不自动等于完整球面全景；投影和可视角度要检查，不拉伸普通照片填满360度。
只使用已审核资源；开发占位明确标注，不能在比赛演示中冒充已完成图文。
本文件列出的来源是核验入口，不是已经获得图片使用许可的素材包。

## 7. 交互与性能

复用现有相机、太阳系、输入和状态管理，不重写全项目。
星球与地点选择保留视觉化体验，同时提供易选中的卡片、搜索和列表，不仅依赖小标记。

地球大量城市标记按视野和筛选显示，避免全部挤在屏幕上；可用分层显示或聚合。城市检索支持名称与常用别名，国家筛选和首都/名城标签。

进入地点采用按对象配置的接近效果：地球可以有大气/云层；其他天体不能机械套用地球式蓝天白云。对木星风暴或土星环使用观察转场，不虚构地表落地。

视觉连续不要求同一巨大场景连续重建：太空三维场景 → 可跳过/取消转场 → 轻量图文/全景/局部模型。

按需加载当前地点资源，返回时清理不用的图片纹理、动画和监听器。只保存轻量目录，不启动时下载所有城市高清图。
离线范围采用明确的内容包与缓存状态：可以离线的包必须实际可用，未缓存条目明确提示。电脑/电视共用内容，平台布局与输入分别适配。

转场取消要恢复相机、星球姿态、焦点与上一个稳定状态，并阻止过期回调。不要靠解除所有动画锁解决返回问题。
城市与地标标记使用真实坐标和统一的旋转变换，随纹理正确旋转。非地球坐标记录坐标系、经度方向和纹理偏移；未知精确位置不伪造坐标。

## 8. 数据结构与内容生产

使用当前工程兼容的结构化数据与校验，不因目录规模大而立即增加复杂后端。

建议实体：
- CelestialBody：标识、类别、名称、简介、事实与来源、视觉参数、探索点。
- CountryEntry：稳定标识、名称/别名、范围来源、版本、首都关系及说明。
- City：稳定标识、国家关联、首都角色或名城标签、坐标、简介、地点/事件。
- Destination：所属天体/城市、类型、坐标/坐标系或位置说明、接近方式、资源、故事、就绪状态。
- Story：标题、日期、简介/正文、主题、关联地点及关系类型、事实来源、审核人/时间。
- Asset：本地/远端路径、原始来源、作者、许可、署名、日期、地点、素材角色和处理说明。
- ContentPack：目录与内容版本、包含的条目和资源、包大小、校验值、离线状态。

清楚区分：目录已收录、资料待核验、素材待授权、内容已就绪。
“首都目录完整”不等于“首都故事已经完整”。覆盖率以明示的目录基线计算，不生成假的完成数量。
同一城市可同时是首都和名城，通过稳定ID去重。

建议生产流程：来源核验 → 内容草稿 → 地点/日期关联检查 → 图片权利检查 → 编辑审核 → 构建校验 → 上线。
Codex可以辅助检索、整理和批量生成草稿，但不能用自动设置的 approved=true 假装人工核验。
发布校验至少检查缺失来源、无效ID、错误资源路径、重复城市、坐标范围、日期、缺失署名与未审核内容。
